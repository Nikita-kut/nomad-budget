# Качество

Почти все ошибки в расчётах денег до сих пор были одного вида: формула верна для «ровного» месяца и ломается, когда что-то происходит посреди месяца (кредит закрыт, счёт убран в архив, сменился платёж) или деньги приходят из другого источника (подушка вместо карты, валютный счёт). Защита строится вокруг этого.

## Слои

| Слой | Где | Что ловит | Когда |
|---|---|---|---|
| Сценарный генератор | `composeApp/src/commonTest/.../scenario/ScenarioInvariantsTest.kt` | нарушение правил на сотнях случайных историй: закрытия посреди месяца, досрочки с подушки и с карты, смены платежа, архив, переводы между подушками | каждый PR (CI) |
| Регрессии | `scenario/RegressionTest.kt`, `tools/rates/test_bank_watch.py` | возврат уже найденных ошибок — каждая с датой | каждый PR (CI) |
| Модульные тесты | `commonTest`, `tools/**/test_*.py`, `supabase/functions/**/*_test.ts` | формулы по отдельности | каждый PR (CI) |
| Чек-лист в PR | `.github/pull_request_template.md`, проверка `tools/quality/check_pr_checklist.py` | забытые сценарии ещё до кода | PR, который трогает расчёты, экраны, бота или базу, без отмеченного чек-листа не проходит CI |
| Независимое ревью | отдельный ревьюер без выводов автора | то, что автор не додумал | перед мержем PR с расчётами |
| Сверка на реальных данных | `tools/quality/reconcile.py` (локально, только чтение) | несостыковки данных и расчётов на настоящей истории | перед каждым релизом и после миграций |
| Приёмка релиза | [RELEASE_CHECKLIST.md](RELEASE_CHECKLIST.md) | то, что видно только глазами | перед тегом |

## Правила, которые проверяет генератор

1. Досрочка с подушки не меняет «Не распределено», «Можно потратить», «Себе» и платежи по кредитам месяца — ни для открытого кредита, ни для закрытого в этом месяце. Подушка за месяц уменьшается ровно на сумму досрочки.
2. Перевод между двумя счетами подушки не меняет ни одной цифры месяца.
3. Архивирование счёта не меняет остаток с прошлого месяца, «Не распределено» и траты по конвертам.
4. Одна величина на разных экранах одинакова: «Себе» в месяце и в графиках, траты по конвертам в месяце и на графике «План и факт», платежи по кредитам с подушки в месяце и в «Капитале», изменение подушки в месяце и в «Капитале», остаток долга в истории и в «Капитале», обязательный платёж на «Кредитах» и в истории.
5. Суммы не отрицательные там, где не могут быть; «осталось» по кредиту не больше плана; всё в базовой валюте.

Тесты проверены подстановкой ошибок (мутациями): по очереди возвращали старые баги и убеждались, что набор падает. Ловятся все 13: досрочка с подушки по закрытому кредиту; «Себе» с платежами по кредитам; закрытый кредит в обязательном платеже; «Себе» в графиках; архивный счёт в остатке; валютный кредит по сегодняшнему курсу; «погашен досрочно» по сегодняшнему остатку; кредит, открытый после дня платежа; копилка в базе вместо её валюты; шаблон досрочки в прошлых месяцах; плитка «Обязательно в месяц» не из истории; будущий месяц с сегодняшним остатком; «План и факт» по всем расходам. Новое правило добавляется так же: сначала тест, который падает на ошибке, потом исправление, потом мутация — убедиться, что тест не проходит «вхолостую».

Генератор строит истории с курсом доллара по дням, кредитами в рублях и долларах (платежи с рублёвой карты и с долларового счёта) и проверяет текущий, прошлый и следующий месяц.

## Чек-лист сценариев

Для каждой величины в деньгах, которую трогает изменение:

1. **Переходы посреди периода:** открыт, закрыт (досрочно или по графику), снова открыт, убран в архив, сменён платёж, сменена база, сменён день начала месяца — в прошлом, текущем и будущем месяце.
2. **Источник и назначение:** жизнь, подушка, копилка, другая валюта, корректировка (системная категория); досрочка и обычный платёж.
3. **Согласованность:** та же величина на других экранах и в боте считается так же, подпись и подсказка совпадают с формулой.
4. **Время:** МСК и пояс пользователя, границы месяца бюджета `[start, end)`, «сегодня» против закрытого месяца.
5. **Валюта:** суммы разных валют не складываются без пересчёта; валюты без копеек и с тремя знаками; сравнение «оплачено ли» — в валюте обязательства, а не в базе по сегодняшнему курсу.

## Сверка на реальных данных

```bash
NOMAD_OWNER_EMAIL=<почта владельца> python3 tools/quality/reconcile.py
```

Скрипт берёт токен Supabase CLI из Keychain и делает только чтение. Он проверяет правила целостности (закрытый кредит без остатка, история платежей у каждого кредита, суммы в текущей базе, тело платежа не больше платежа и т. д.) и печатает факты текущего месяца владельца: доход по плану, остаток с прошлого месяца, конверты, «Себе», платежи по каждому кредиту по источникам. Код выхода 1 — релиз не делаем. Факты сверяются с экранами «План» и «Кредиты». Правила целостности проверяются по всем пользователям, но подробности (названия, id) печатаются только по владельцу; по остальным — число нарушений под обезличенным номером. В CI скрипт не запускается: в выводе суммы владельца, а логи репозитория публичные.
