# Бэкапы

На бесплатном тарифе Supabase своих бэкапов нет, поэтому дамп снимает workflow «Backup» каждую ночь в 02:00 МСК.

1. Роль `backup_reader` только читает: `default_transaction_read_only`, select на `public`, пользователи Auth — через `backup.auth_users()` и `backup.auth_identities()`. Роль и функции создаёт миграция 0024; пароль задаётся вне миграций и лежит только в секрете `PROD_DB_URL`.
2. Дамп данных `public` (pg_dump 17) и пользователи Auth в JSON.
3. Проверка восстановления: пустой Supabase из миграций репозитория, загрузка дампа, сравнение числа строк по каждой таблице с продом. Расхождение — workflow падает, владельцу приходит оповещение. В лог попадают только названия таблиц, не данные.
4. Архив шифруется `age` публичным ключом из переменной `BACKUP_AGE_RECIPIENT`. Закрытый ключ — только у владельца, в CI его нет.
5. Архив кладётся в приватный репозиторий `nomad-budget-backups`. Хранятся 30 дней. Ветка каждую ночь пересобирается одним коммитом, так что удалённый дамп не остаётся в истории.

## Восстановление вручную

```bash
age -d -i ~/nomad-backup.age.key dumps/ДАТА.tar.gz.age | tar -xzf -
```

Дальше — как в `tools/backup/restore_check.sh`: схема из миграций, `session_replication_role = replica`, пользователи Auth из JSON, затем `public.sql`. Перед восстановлением прода — дамп текущего состояния.
